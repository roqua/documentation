* in the repo, visible in the admin area (#816)
  
  This makes the release notes part of the PR that makes the change: a
  markdown file under
  `doc/release_notes/`, in Dutch, aimed at a non-technical reader. CI
  refuses a PR without
  one, and the deploy is what publishes the note — customers then read it
  in the admin area.
  Notes marked `internal` are never shown, which lets "every PR adds a
  note" be a rule with
  no exceptions. Root accounts can correct a published note afterwards.
  
  This is stage 1 of
  `doc/features/release_policy_architectural_support.md`; no email
  (stage 2) and no feature flags (stage 3/4).
